## 1. Executive Summary & Scientific Audit Remediation

This report documents the end-to-end scientific, geospatial, and engineering audit of **NISAR — Dancing with the SARs**:

1. **Scientific & Software Defects Discovered and Fixed During Audit:**
   - **Domain 1 Reference Georegistration & Sensor-Independence Defect Fixed (`scripts/acquire_real_sar_data.py`):** The earlier `thessaly_s2_20230915_ndwi_flood_ref.tif` had subtracted pre-event water by reading `s1_base.read(1, out_shape=(out_h, out_w))` without `rasterio.warp.reproject`, shifting the subtracted baseline reservoir mask by `~300–400 m` (`s1_base` bounds `[22.7966, 39.4476, 22.9537, 39.5824]` vs. Sentinel-2 window bounds `[22.7931, 39.4451, 22.9574, 39.5850]`) and leaking Sentinel-1 SAR into the optical reference. Regenerating `thessaly_s2_20230915_ndwi_flood_ref.tif` purely from **Sentinel-2A MSI L2A (`B03`/`B08` NDWI, `2023-09-15`) + properly `reproject`-aligned JRC Global Surface Water + Copernicus DEM (`<= 5°` slope)** with `nodata=255` — **without changing any Domain 1 SAR threshold** (`bounded_otsu = -15.1 dB`, `min_drop_db = 3.0 dB`) — increased Domain 1 validation accuracy from `IoU = 18.5% / F1 = 31.3%` to **`IoU = 40.1% / F1 = 57.2% / Precision = 72.5% / Recall = 47.3%`**.
   - **Binary Confusion Matrix NoData Exclusion & `nodata=255` Encoding Fixed (`backend/app/utils/validation.py` & `backend/app/services/seed_service.py`):** Previously, `tn_mask = ~pred_positive & ~ref_positive` lacked `& ref_valid`, causing `NaN`/NoData pixels to be counted as True Negatives (`TN`), and synthetic `0/1` `uint8` benchmark masks were written with `nodata=0` (turning negative class `0` into `NaN`). `tn_mask` now strictly requires `& ref_valid`, all binary `0/1` `uint8` masks use `nodata=255`, and both `valid_evaluated_pixels` and `missing_or_nodata_pixels` are reported explicitly.
   - **Geographic CRS Spatial Resolution Calculation Fixed (`backend/app/utils/validation.py`):** Computing `round(abs(base_raw.transform.a), 1)` on `EPSG:4326` rasters previously rounded `0.000833°` (`~92.6 m`) to `0.0 m`. `spatial_resolution_m` now converts degree pixel sizes to metres using `sqrt(pixel_area_m2)`.
   - **Multi-Method Comparison Runtime Isolation Fixed (`backend/app/utils/validation.py`):** The candidate-method loop previously executed inside the primary method's `time.perf_counter()` block, inflating the primary method's reported `runtime_ms`. Each method's execution timer is now strictly isolated.
   - **Explicit 4-Tier Reference Independence Classification (`backend/app/schemas/results.py` & `backend/app/utils/validation.py`):** Every validation result now reports both `validation_category` and `reference_independence` across four explicit tiers:
     1. `independent_cross_sensor` (`validation_category="independent_real_reference"`) — Domains 1, 2, 5.
     2. `partially_independent_cross_pair` (`validation_category="partially_independent_real_reference"`) — Domain 4 (two real interferograms sharing the `2021-03-09` post-seismic Sentinel-1A pass, LiCSAR frame `102A_04971_141314` processing chain, and far-field reference tie window).
     3. `climatological_comparative_baseline` (`validation_category="climatological_comparative_reference"`) — Domain 3 (`2022` annual ITS_LIVE mosaic vs. multi-year ITS_LIVE static climatology from the same NASA MEaSUREs processing suite).
     4. `synthetic_benchmark` (`validation_category="demonstration_synthetic_benchmark"`) — Synthetic benchmark fixtures (`is_synthetic=True`).
   - **Planetary Computer Cross-Collection STAC Search Defect Fixed (`backend/app/api/endpoints/explorer.py`):** Passing `collections: ["sentinel-1-rtc", "cop-dem-glo-30"]` in a single POST `/api/stac/v1/search` caused Planetary Computer to return `HTTP 400 ("Cross-collection searches require all collections to use the same backend")`, which was caught and misreported as `offline_or_blocked`. `_query_external_stac` now queries each collection individually and merges the discovered items (`status: "connected"`).
